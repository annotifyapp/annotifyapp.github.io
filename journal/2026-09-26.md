# 2026-09-26

This plan is for a multi-agent learning project featuring current low-cost [not zero-cost] tooling and API prices first. The 4-week plan stays well under a $500 cap cost, yielding skills that keep it operational for staying well under a $100/month ceiling for ongoing operation.

This plan follows the earlier bias: **LangGraph is the production brain**, **Hermes is the daily operator**, **[CrewAI](https://docs.crewai.com/)** is part of this as [a short trial dose](https://app.crewai.com/crewai_plus/settings/billing)** in order to learn the role/task patterns of [CrewAI Flows](https://docs.crewai.com/v1.15.22/en/guides/flows/first-flow) and [Crew AI Crews](https://docs.crewai.com/v1.15.22/en/guides/crews/first-crew) without necessarily living in the [realm of the paid service using lightweight CrewAI ochestration framework infrastructure OR using CrewAI forward deployed engineers as an alternative to the more substantial enterprise-grade Palantir](https://share.google/aimode/ZJdqpZeBgkNMHAMbJ). 

The point of this learning project is build a practical, REAL (ie personal) self-monitoring **Intelligence + Relationship OS** that I will actually use and continue to learn from ... it's not supposed to be just a tutorial graveyard, but at some point, I might decide that it actually makes sense for me to *use* the Palatir approach, just to be more familiar with the offering of $PLTR. Mostly, this system is just for my own personal needs and I do not intend to become a forward deployed engineer working for Palantir or for clients who need Palantir-grade systems.

Two hard rules for this domain:
- Agents **draft and gather intelligence**, but only MZB actually **sends, trades, or makes big decisions**.
- Strongly prefer **free public data + local files** over paid intelligence or data ... although there may be a role for things like DeepVue.

## What I expect to have after 4 weeks

A local system that, every morning:

1. Pulls new **arXiv / OpenAlex / Semantic Scholar** items in my fields  
2. Pulls **market / macro / filings / news** items for a small watchlist  
3. Scores, summarizes, and files them into a markdown vault  
4. Updates a **relationship CRM** (researchers + information sources)  
5. Drafts follow-ups and a daily brief  
6. Stops before email send or trade execution  

Stack: Python + LangGraph + SQLite + markdown vault + Hermes profiles. CrewAI only in week 1.

```text
Sources (RSS/API/IMAP)
        ↓
Ingest + dedupe          ← cheap / no model
        ↓
Triage graph node        ← cheap classifier
        ↓
        ├─ Papers path: summarize, authors, “should I email?”
        ├─ Markets path: event → thesis impact → watchlist note
        └─ Relationship path: parse mail/feed → CRM update + draft
        ↓
Human gate
        ↓
Vault + SQLite + daily brief
```

Hermes sits **above** this as the operator I talk to: “what mattered today?”, “draft a note to X”, “watch this author.”  
LangGraph is the **scheduled machine**.  
CrewAI is the **role sketch** I will probably throw away after week 1.

## Week 1 — Foundations, sources, CrewAI dose  
**Outcome:** vault + DB + source connectors + one CrewAI prototype I will not keep.

- Write `README.md`: 8–12 preprint topics, 8–12 tickers/themes, 15 people/institutions to watch.
- Create repo: `vault/`, `crm/`, `graphs/`, `hermes/`, `learn/`, `ops/`.

### Day 5 — Single-agent baseline

- Time it. Cost it. This is the baseline LangGraph must beat on *control*, not on poetry.

## Week 2 — LangGraph papers + researcher CRM  
**Outcome:** durable preprint graph with checkpoints and a human gate.

### Day 7 — Graph state
Typed state only:
`item_id, source, title, abstract, authors[], scores, summary, actions[], errors[]`  
Nodes: `ingest → triage → enrich → summarize → crm_suggest → brief_append → human_gate`.  
Checkpoint to SQLite/file. If it crashes, resume. That is the LangGraph lesson.

### Day 8 — Triage that is cheap
Classifier output: `{domain, relevance 0-5, novelty, method_vs_survey, watchlist_hit}`.  
Drop score <3 before any expensive summary. This is the main money control.

### Day 9 — Enrichment without PDFs first
Use metadata only: authors, affiliations (S2), citation count, related papers, open PDF link.  
Full-PDF reading is a later, rare node. PDFs are how bills explode.

### Day 10 — Relationship intelligence
For each kept paper:
- upsert authors
- if author is new and relevance ≥4, create `open_loop`: “worth a short note?”
- never auto-email
Draft template only: 4 sentences, specific, cite their paper, one question, my work in one line.

### Day 11 — Human-in-the-loop
LangGraph interrupt before:
- anything marked `email_draft`
- anything marked `add_to_priority_reading`
I approve in terminal or a tiny markdown queue `queue/today.md`.

### Day 12 — Eval set
Pick 25 papers from the last 10 days. Blind-score graph vs Day 5 script.  
If graph is not more precise on *my* topics, fix triage, not prompts.  
Cost log: stay near a few dollars.

## Week 3 — Markets path + Hermes as relationship manager  
**Outcome:** second graph + Hermes profiles that operate the system.

### Day 13 — Markets graph
Same discipline, different schema:
`event → instrument/theme → claim → evidence → confidence → trading_implication → not_advice_flag`  
Implications are labels (`vol_up`, `event_risk`, `thesis_hurt`, `ignore`), not orders.

### Day 14 — Separate facts from takes
Two vault folders:
- `markets/facts/` filings, prints, official releases  
- `markets/takes/` blogs, Twitter/X summaries, news  
Agents must tag the difference. Mixing them is how trading research becomes fan fiction.

### Day 15 — Hermes profiles
Create 4 profiles, different tools and models:
- `operator` — talk to me, call tools, never send mail  
- `papers` — read vault + DB  
- `markets` — read facts/takes  
- `crm` — people and drafts only  

Use worktrees/delegate for parallel “scan papers” and “scan markets.” Operator synthesizes.

### Day 16 — Email / newsfeed parsing
Connect **only** the research mailbox or a Gmail label (`intel`).  
Graph/Hermes extract: sender, intent (`paper`, `intro`, `meeting`, `noise`), due date, draft reply.  
I paste or approve. I will UNSUBSCRIBE / filter noise at the mail client, not in the LLM.

### Day 17 — Daily brief product
One page, 15 minutes to read:
- 5 papers (1 line + why it matters to me)
- 5 market events (fact vs take)
- 5 CRM open loops
- 3 optional drafts  
Hermes command: `/brief`. LangGraph job writes the file first; Hermes only narrates.

### Day 18 — Cost and reliability drill
- Force a crash mid-run; resume from checkpoint.  
- Cap nodes, timeouts, max papers/events per run (e.g. 40 ingest, 8 summaries).  
- If Plus is on, measure Tool Gateway vs raw APIs. Keep APIs as default.

### Day 20 — Researcher workflow end-to-end
Take 3 real papers I care about. Produce:
- notes
- author cards
- work on at least one *unsent* note or note needing improvement, ie if I would not send the note myself, the agent failed ... *BUT, that's an OPPORTUNITY to improve -- how should the note be* ***intelligently*** *corrected?*

### Day 21 — Trading research end-to-end
Take one live theme on my watchlist. Produce a one-page dossier: facts, competing takes, what would change my mind, what is still unknown.  
Optional: paper-trade journal entry written by me, not the agent.

### Day 22 — Evaluation harness
20 frozen items (10 paper, 10 market). Rerun after prompt changes.  
Metrics: precision@keep, hallucination on numbers/authors, draft quality, $ per brief.  
This is the habit that makes the system improve after the course.

Recommended steady stack: Hermes + Portal Plus $20 + cheap-model remainder $10–40 + everything else $0.

what the graph does, what Hermes does, what I still do, cost, next 90 days.
